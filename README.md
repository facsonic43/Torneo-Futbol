# Football Championship

Java 25 / Maven project for `TPGrupal-2026-Campeonato Futbol.pdf`.

## Reports, statistics and rankings (section E)

Run `run.RunChampionship` in IntelliJ with the project root as the working directory.
It loads `src/main/resources/torneo.json` and runs the championship simulation.
Generate the PDF from the live `ReportData` instance with the report API shown below.
`RunChampionship` intentionally does not create a PDF automatically, so the simulation
flow from the main project stays independent of the reports module.

Reports are implemented in `PDF` and `reports`, using a `ReportData` wrapper for
report-specific information.

### Player photos and initial profiles

Place real player photos in `photos/`, or pass another directory to the report API.
Use the player's identity document as the filename: `<idType>-<idNumber>.jpg` or
`<idType>-<idNumber>.png`, for example `DU-10000001.jpg`. Missing images are marked
**Photo unavailable** on the participant identification card. A supplied image that
cannot be read produces an export error. No photos are supplied by the JSON or
generated by the application.

`ReportData.fromInitialData(tournament)` reads initial player skills and referee
experience from `torneo.json`, because the existing model does not expose every
profile field. This report-specific metadata does not change the participants or
their historic statistics. If the initial file is absent, unavailable details stay
unavailable; a malformed or unreadable file produces an explicit error. Use
`new ReportData(tournament)` when an initial JSON profile is not needed.
For participants created outside the initial file, supply these details through
`reportData.setRefereeExperience(referee, years)` and
`reportData.setPlayerSkills(player, skills)`, where `skills` maps skill names to
integer ratings from 0 to 100.

### Connecting reports to the rest of the project

Create one `ReportData` wrapper for the live `TournamentData` instance. Register
groups and matches in that report wrapper as colleagues create them. Group matches
are included automatically from registered groups; register standalone and knockout
matches with `addMatch`. The wrapper's match snapshot removes duplicate references.

```java
import PDF.PDFGenerator;
import reports.ReportData;
import reports.ReportOptions;

import java.nio.file.Path;

ReportData reportData = ReportData.fromInitialData(tournamentData);
reportData.addGroup(group);
reportData.addMatch(match);

// Run after the championship has played or updated matches; handle IOException.
PDFGenerator.generate(reportData, Path.of("UpdatedReport.pdf"), ReportOptions.defaults());
```

For a filtered export, pass `new ReportOptions(position, player, photosDirectory)`.
Use `null` for all positions or all players. A selected player must match the selected
position. The compatible `new PDFGenerator(tournamentData)` constructor generates
the initial report, while exporting from `ReportData` includes its registered
groups, matches and additional reporting details.

The current models do not expose all information required for exact match reports.
The team can supply those details through the report wrapper without changing the
shared model classes:

```java
// Lists of the actual starting players for each side.
reportData.getMatchDetails(match).setStartingPlayers(homeStarters, awayStarters);

// Whether this goal was a match penalty or an own goal, and who conceded it.
reportData.getMatchDetails(match).setGoalDetails(goal, penalty, ownGoal, receivingGoalkeeper);
```

Register the actual starters to calculate minutes accurately from substitutions
and dismissals, and provide the goal details for penalty, own-goal and
goalkeeper statistics. Supply this information alongside the existing match objects;
the report does not change or simulate the championship. Missing information must
not be interpreted as confirmed zero activity. Starting the application again loads
the initial JSON; it does not restore an earlier simulated championship.

### Statistical criteria

Championship rankings use only registered matches marked as played. Historical
statistics loaded from `torneo.json` remain identified separately in participant
and player details.

- Goals, assists, cards and goalkeeper goals conceded use match events and any
  additional reporting details supplied by the championship. Penalty shootout goals
  do not count as scorer goals or goalkeeper goals conceded; penalties scored during
  the match do count.
- Team efficiency is `100 * points / (3 * matches played)`, with three points for a
  win and one for a draw. A match tied before a penalty shootout counts as a draw
  for this statistic.
- Fair Play uses `yellow cards + 3 * red cards`; fewer points rank first. This is
  the report's explicit weighting because the assignment does not specify one.
- Average age uses the current ages of the full squad. Average referee experience
  uses the available years of experience in the referee profiles.
- Before the draw or before matches are played, the report shows pending brackets
  and the absence of championship results. It does not invent fixtures or winners.
- The bracket uses the assignment's zone pairings and two-leg qualification rules.
  Incomplete or unresolved results remain pending until the championship provides
  the required matches and results.

Build and run the automated checks with `mvn test` (JDK 25 required).
